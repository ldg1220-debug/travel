## 2. ★★★ 남은 4건은 전부 "시설 동반 스팟"입니다

```
오사카 day1 (3곳): 유니버설 스튜디오 재팬
                 > COLONY by EQI Shinsaibashi Amemura
                 > 규카츠 모토무라 난바 분점
```

이 동반 2곳이 **난바 청크에서 뽑혀 나온 것**입니다.

```
363m  COLONY(d1)          ~ 도톤보리(d2)
393m  COLONY(d1)          ~ 신사이바시스지(d2)
239m  규카츠 난바 분점(d1)  ~ 도톤보리(d2)
```

**위반 4건 중 3건이 이 둘 때문입니다.** 청크는 안 쪼개기로 했는데,
`capAllDayFacilityDays`가 스팟 단위로 최근접 2곳을 고르면서 청크를 깹니다.
세션이 보고서에 적은 그 지점이 실제로 드러난 것입니다.

후쿠오카도 같은 구조입니다.

```
day1 (3곳): 마린월드 우미노나카미치 > 후쿠오카 타워 > 후쿠오카 시 박물관
```

**마린월드는 우미노나카미치 반도, 타워·박물관은 모모치 해변입니다.**
사이에 하카타만이 있어 8km를 돌아가야 합니다. 위반은 없지만 코스로는 어색합니다.

### 수정 — 시설 날은 시설만 두세요

```
capAllDayFacilityDays:
  시설이 있는 날은 시설 1곳만 남긴다 (동반 스팟을 붙이지 않는다)
  빠진 스팟은 자기 청크가 있는 날로 돌려보낸다
```

**1곳짜리 날이 문제였던 건 편차 계산 때문이었는데, 그건 이미 해결됐습니다.**
지금은 시설 날을 편차에서 제외하니 1곳이어도 아무것도 안 깨집니다.

그리고 실제로 그게 맞습니다 — USJ와 마린월드는 **그것만으로 하루가 찹니다.**
억지로 두 곳을 붙이니 반대편 동네가 딸려와서 이틀에 걸쳐 같은 골목을 걷게 됩니다.

> 이 변경으로 남는 스팟이 2곳 늘어납니다. `trimToCapacity` 공식도
> `시설 날 수 × 1 + 일반 날 수 × 6` 으로 맞춰주세요.

## 3. ★★ 남은 1건 — 6곳 상한이 밀집 구역을 자릅니다

```
493m  규카츠 모토무라 난바 분점(day1) ~ 구로몬 시장(day3)
```

`구로몬 시장`이 우메다 날(day3)에 있습니다. 난바인데요.
난바 날(day2)이 6곳으로 꽉 차서 밀렸습니다.

오사카 2일 코스에서도 같은 일이 보입니다.

```
day1 6곳 11.03km : … 우메다 스카이빌딩 > 쓰텐카쿠 전망대 > 아베노하루카스
```

**쓰텐카쿠·아베노하루카스는 텐노지**인데 우메다 날에 붙었습니다. 난바 날이 꽉 차서입니다.

### 수정 — 청크가 통째로 들어갈 때만 7곳 허용

```
하루 상한 6곳 (기본)
  단, 청크 하나를 통째로 넣어야 하고 그러면 7곳이 되는 경우에 한해 7곳 허용
```

**청크를 쪼개는 것보다 한 곳 더 많은 게 낫습니다.**
지난 다섯 번의 교훈대로, 숫자를 맞추려고 지리를 깨뜨리지 마세요.
