## 1. ★★★ `totalDistanceKm`가 직선거리 합입니다

응답값과 제가 계산한 하버사인(직선) 합을 비교했습니다.

| 지역 | API `totalDistanceKm` | 직선거리 합 | 차이 |
|---|---|---|---|
| 경주 d1 | 3.2 | 3.19 | **0.01** |
| 통영 d1 | 27.7 | 27.68 | **0.02** |
| 오사카 d3 | 13.6 | 13.64 | **-0.04** |

**소수점 둘째 자리까지 일치합니다.** 도로 거리가 아니라 직선거리입니다.

---

## 2. ★★★ `toNextMinutes`도 계산값입니다

통영 구간별로 속도를 역산했습니다.

```
사량도 → 중앙활어시장       21.05km / 51분 / car   → 24.8km/h
중앙활어시장 → 심가네해물짬뽕  0.56km /  7분 / walk  →  4.8km/h
심가네해물짬뽕 → 디피랑       0.72km /  9분 / walk  →  4.8km/h
디피랑 → 클라우드힐          2.80km /  7분 / car   → 24.0km/h
클라우드힐 → 저녁마실         2.56km /  6분 / car   → 25.6km/h
```

**walk가 두 번 다 정확히 4.8km/h입니다.** car는 24~25.6km/h.
`직선거리 ÷ 고정 속도`입니다. 실제 경로를 조회한 값이 아닙니다.

### 그래서 이런 게 나옵니다

```
사량도 → 중앙활어시장 : 21km, 차량 51분
```

**사량도는 섬입니다.** 통영항에서 배로 들어갑니다.
직선 21km 사이에 바다가 있고, 차로는 갈 수 없습니다.
그런데 블로그에는 이렇게 나갔습니다.

```
총 이동 27km · 6곳 · 약 1.2시간
이동수단: 차량, 도보 기준
```

**채널 정체성이 "실제 평점·동선 데이터로 검증한 코스"입니다.**
평점·리뷰수는 진짜인데 동선은 계산값입니다. 여기가 제일 아픈 지점입니다.

## 3. 수정 — 실제 경로 조회

```
국내 : 카카오모빌리티 길찾기 API (자동차) — 무료 쿼터 있음
해외 : Google Directions API
```

구간마다 1회 호출해 **거리·소요시간·경로 폴리라인**을 받으세요.

| 항목 | 지금 | 변경 |
|---|---|---|
| `toNextMinutes` | 직선 ÷ 고정속도 | 경로 API의 `duration` |
| 구간 거리 | 직선 | 경로 API의 `distance` |
| `totalDistanceKm` | 직선 합 | 경로 거리 합 |

### 비용은 크지 않습니다

3일 코스가 스팟 13곳이면 **구간 12개**입니다.
`course_cache`에 이미 저장되니 **지역·일수 조합당 1회**만 호출합니다.
캐시 버전을 올릴 때만 다시 돕니다.

### ★ 경로를 못 찾으면 그 스팟을 빼세요

```
경로 조회 실패 또는 소요시간이 비정상적으로 큼(예: 3시간 초과)
  → 그 스팟을 코스에서 제외
  → 3곳 미만이 되면 C-2 계약대로 해당 지역 스킵
```

**사량도 같은 섬이 이 규칙으로 자동으로 걸러집니다.**
지금은 "차로 51분"이라고 단언하는데, 못 가는 곳을 갈 수 있다고 쓰는 게 제일 나쁩니다.

## 4. ★★ 지도의 선도 직선입니다

동근님이 처음 짚으신 부분입니다.

```
경주 지도: ① → ④ 가 시가지·하천을 가로질러 일직선
```

Google Static Maps의 `path=`에 좌표만 넘기면 **측지선(직선)** 이 그려집니다.
도로를 따라가게 하려면 경로 폴리라인이 필요합니다.

```
Directions API 응답의 overview_polyline.points 를 그대로:
  path=enc:{overview_polyline}
```

**§3을 하면 폴리라인이 이미 손에 들어옵니다.** 지도는 그걸 넘기기만 하면 됩니다.
따로 호출할 필요 없습니다.
