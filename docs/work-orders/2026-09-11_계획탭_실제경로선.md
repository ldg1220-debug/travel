## 2. ★★★ 계획 탭 동선이 아직 직선입니다

`course-brief` 지도(#242)는 도로를 따라가는데, **계획 탭 지도는 그대로 직선**입니다.
스팟 사이를 점선 직선이 가로지릅니다.

### 실측 — 경로 조회를 아예 안 합니다

계획을 연 뒤 네트워크 요청 전부입니다.

```
maps.googleapis.com/…/geometry.js     ← 좌표 계산
maps.googleapis.com/…/poly.js         ← Polyline 그리기
tradule.co.kr/api/itineraries  POST
```

**Directions 호출도, 트레쥴 경로 API 호출도 없습니다.**
좌표 두 개를 `Polyline`으로 잇는 것이 전부입니다.

### 왜 고쳐야 하나

`course-brief`에서 이미 확인한 그대로입니다. 직선은 **산·바다·강을 그냥 가로지릅니다.**
계획 탭은 사용자가 직접 만드는 화면이라 더 자주 보게 됩니다.

그리고 **일정 시각도 같은 문제를 안고 있습니다.**

```
구로몬 시장     09:00 · 60분
규카츠 모토무라  10:06 · 60분    ← 6분 이동
도톤보리        11:09 · 60분    ← 3분 이동
```

코스에서 불러온 일정은 #242의 실제 경로 값이라 맞지만,
**사용자가 장소를 직접 추가하면 그 구간은 다시 추정값**이 됩니다.
한 일정 안에 실제값과 추정값이 섞입니다.

## 3. 수정 — #242에서 만든 것을 재사용하세요

`fetchKakaoDrivingRoute` / `fetchGoogleDirectionsRoute`가 이미 있습니다.
**새로 만들지 말고 엔드포인트로 노출**하세요.

```
POST /api/routes
  { legs: [{ fromLat, fromLng, toLat, toLng, mode }] }
  →  [{ distanceM, durationMin, polyline }]
```

```
계획 지도:  polyline 을 Polyline 으로 그린다
일정 시각:  durationMin 으로 다음 장소 시작 시각을 계산
```

### 호출을 아끼는 규칙 ★

계획은 드래그할 때마다 바뀝니다. **그대로 두면 요청이 폭주합니다.**

```
· 변경 후 800ms 디바운스 — 드래그 중에는 호출하지 않음
· 바뀐 구간만 다시 조회 (앞뒤 2개 구간)
· (출발 placeId, 도착 placeId, 모드) 로 캐시 — 같은 쌍은 재사용
```

### 경로를 못 받으면 직선으로 두되, 다르게 보이게

```
경로 있음  →  실선, 도로를 따라감
경로 없음  →  지금처럼 점선 직선 + 시간 표시 안 함
```

**점선을 "추정" 표시로 쓰세요.** 지금은 전부 점선이라 구분이 없습니다.
사용자가 어느 구간이 실제 값인지 알 수 있어야 합니다.

## 4. ★ 곁가지 — 제휴 스크립트가 계획 페이지에서 오류를 냅니다

계획 페이지에서 이 요청들이 나갑니다.

```
emrldtp.com/chunk.CcgReWIh.js
emrldtp.com/link-switch/v1/convert?location=…/planner/8b7e8761-…&trs=563085
emrldtp.com/collect   →  503
emrldtp.com/collect   →  503
emrldtp.com/collect   →  503
```

트래블페이아웃 링크 변환 스크립트입니다(`trs=563085`).

| 문제 | 내용 |
|---|---|
| 503 3회 | 매 페이지 로드마다 실패 요청 |
| 토큰 노출 | `location`에 **계획 공유 토큰이 그대로** 담겨 외부로 나갑니다 |

계획 페이지에는 제휴 링크가 없으니 **이 스크립트를 로드할 이유가 없습니다.**
제휴 링크가 실제로 있는 페이지에만 넣으세요.
공유 토큰은 그 자체가 접근 권한이라 외부 전송은 피하는 게 맞습니다.
