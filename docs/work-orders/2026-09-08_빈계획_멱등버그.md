## 1. ★★★ 증상 — 독자가 빈 플래너를 봅니다

블로그 글의 **"트레쥴에서 경주 코스 보기"** 를 누르면 이렇게 됩니다.

```
/api/content/course-open?region=경주&days=1
  → /planner/693d6171-2b62-4d81-945d-c391fadda00c

  9/6 (일)  0개 장소
  9/7 (월)  0개 장소
  9/8 (화)  0개 장소
```

**장소가 하나도 없습니다.** 새로고침해도 같습니다. 일시적인 게 아닙니다.

같은 시각 `course-brief?region=경주&days=1`은 스팟 4곳을 정상 반환합니다.
**브리프에는 코스가 있는데 플래너에는 없습니다.**

이게 지금 가장 아픈 지점입니다. 블로그에서 앱으로 넘어오는 **유일한 동선**인데,
넘어온 독자가 빈 화면을 봅니다.

## 2. 원인 추정 — 멱등 처리가 빈 계획을 영구 재사용합니다

다른 지역은 정상입니다.

| 호출 | 결과 |
|---|---|
| `course-open?region=통영&days=1` | ✅ 6곳 |
| `course-open?region=오사카&days=2` | ✅ 5곳 + 7곳 |
| `course-open?region=경주&days=1` | ❌ **0곳** |

경주만 비어 있고, 두 번 열어도 **같은 `shareToken`** 이 나옵니다.

PR #233의 "course-open 멱등 처리" 때문으로 보입니다.
**언젠가 스팟이 없는 상태로 한 번 만들어진 계획이, 이후 영원히 재사용됩니다.**
그 사이 알고리즘이 여섯 번 바뀌었는데도 그대로입니다.

### 수정

```
멱등 재사용 조건에 "저장된 계획에 스팟이 1곳 이상" 을 추가
  → 비어 있으면 재사용하지 말고 새로 만든다

계획 생성 시 스팟이 0곳이면 저장하지 말 것
  → 빈 계획을 만들어 두는 것 자체가 문제
```

`COURSE_ALGO_VERSION`을 멱등 키에 포함하는 것도 함께 검토해 주세요.
`course_cache`에는 이미 버전이 들어가는데, **계획 쪽에는 없습니다.**
알고리즘이 바뀌어도 예전 코스가 계속 열립니다.

> 이미 만들어진 빈 계획이 다른 지역에도 있을 수 있습니다.
> 스팟 0곳인 계획을 조회해서 정리해 주세요.

## 3. ★★ 계획 일수가 요청과 다릅니다

```
days=1 요청  →  플래너 3일 (경주) / 2일 (통영)
days=2 요청  →  플래너 4일 (오사카)
```

```
오사카 days=2
  9/8 (화)  5개 장소
  9/9 (수)  7개 장소
  9/10 (목) 0개 장소     ← 빈 날
  9/11 (금) 0개 장소     ← 빈 날
```

**요청한 일수만큼만 만드세요.** 빈 날짜 칸이 붙어 있으면
독자는 "일정이 덜 짜였다"고 읽습니다. 코스가 완성된 것으로 보이지 않습니다.
