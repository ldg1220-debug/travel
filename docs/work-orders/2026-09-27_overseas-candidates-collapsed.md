## 처리 결과 (이 세션이 추가)

이 지시서는 뒤이어 도착한 "Places API 비용 절감" 지시서의 A-6과 사실상
같은 요구(호출 실패 로그 + 실패 캐시 금지)라 두 지시서를 한 라운드에
같이 처리했다 — 자세한 처리 결과는
`docs/work-orders/2026-09-27_places-api-cost.md`에 정리했다. 이 문서에는
그 문서에서 다루지 않은 항목만 기록한다.

### A-1 — 완료 (원인 규명 + 로그 추가 + 422/503 구분)

**정확한 원인은 로그 없이는 확정할 수 없었다** — 그게 바로 이 지시서의
핵심 문제였다. `src/lib/server/courseRecommend.ts`의 `googleTop`을 읽어
직접 확인한 사실: Google Places 호출이 실패(`!res.ok`)하면 상태코드도
남기지 않고 조용히 빈 배열을 반환하고 있었다 — 지시서가 지적한
"Vercel 로그에 아무것도 안 남는다"는 문제의 정확한 코드 위치를 찾았다.

- 실패 시 상태코드·응답 본문을 `console.error`로 남기도록 고쳤다.
- 후보가 비정상적으로 적을 때 캐시하지 않는지 확인한 결과, **이미 두
  겹으로 되어 있었다**: (1) 원본 검색 결과 캐시(`place_candidate_cache`)는
  빈 결과를 애초에 캐시하지 않고(`fetchSlotCandidates`의 기존 주석이
  "API 실패인지 진짜 결과 없음인지 구분 못 해 항상 재시도하게 둔다"고
  이미 설명하고 있었다), (2) 최종 코스 캐시도 `isCacheableBrief`/
  `minViableSpots` 기준 미달이면 쓰지 않는다(작업지시서 2026-09-23
  "자동 코스 일수 확장" §4에서 이미 구현됨). 새로 손댈 곳이 없었다.
- **이번에 새로 구현한 것**: "실패해서 얇아진 결과"와 "원래 얇은
  지역"을 구분해, 전자는 422 대신 503으로 응답하게 했다(뒤이은 지시서
  A-6이 명시적으로 요청한 항목 — 자세한 구현은
  `2026-09-27_places-api-cost.md` 참고).
- 원인 자체(쿼터 초과/키 오분기/질의 변경 중 무엇인지)는 **아직도 확정
  못 했다** — 키 분기는 코드를 확인해 `GOOGLE_MAPS_SERVER_KEY`가 Places
  호출에 섞이지 않는다는 것만 확인했다(overseas Places 호출은
  `GOOGLE_PLACES_API_KEY`/`NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`만 쓴다,
  courseRecommend.ts:753). 쿼터 초과 여부는 Google Cloud 콘솔 접근이
  필요해 이 세션이 확인할 수 없다 — 이제부터는 로그에 상태코드가 남으므로
  Cowork가 다음 재현 때 바로 원인을 알 수 있다.

### A-2 — 이번 라운드에서 다루지 않음

24개 코스 페이지 URL 목록 제공(엔드포인트 또는 보고 첨부)은 이번
라운드의 범위(A-1 최우선)에 집중하느라 다루지 못했다. `ENABLED_COURSE_PAGES`
(`src/lib/coursePages.ts`)가 이미 그 목록을 코드로 갖고 있어 다음
라운드에서 가볍게 구현할 수 있다.

### A-3 — 이번 라운드에서 다루지 않음

버전 상승 시 사전 워밍 절차는 `2026-09-27_places-api-cost.md`의 A-3
(운영 규칙)과 겹치는 주제라 그쪽에서 함께 다루기로 하고 이번엔
보류했다.

### A-4 — 이번 라운드에서 다루지 않음

코스 페이지 내부 링크는 SEO/UX 개선 항목으로, 이번 라운드는 A-1(생산
중단급 버그)에 집중했다. 별도 라운드가 필요하다.

### A-5 — 이번 라운드에서 다루지 않음

"경주 용황 광 옛날통닭 치킨 맥주 호프 저녁 야식" 같은 나열형 상호명
정제는 이번 라운드에서 다루지 못했다. 실제 업체명이 원래 이렇게 등록돼
있는 경우(카카오/구글 원본 데이터)와 파이프라인이 여러 키워드를
이어붙인 경우를 구분해야 정확한 해법(대체 이름 vs 순위 하향)을 고를 수
있는데, 이 세션은 라이브 데이터를 조회할 수 없어 어느 쪽인지 확인하지
못했다.

### 이전 지시서와의 관계(비단조 버그) — 아직 이어서 하지 않음

A-1(실패 로그)은 이번에 됐지만, "후보 수집을 일수와 분리"하는 전면
재구조화는 여전히 하지 않았다 — `2026-09-27_places-api-cost.md`의 A-2가
같은 작업을 요청하고 있어 그 문서 처리 결과에서 다룬다.
