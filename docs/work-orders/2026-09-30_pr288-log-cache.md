## 1. ★★★ 문제

KK · 세부 v22 결과는 **이미 서버 캐시에 있습니다**(9/29~30 Cowork 실측 때 생성).
버전이 22 그대로라 다음 호출은 `path=cache-hit` 으로 끝나고, `days-generated` · `composed` · `post-route-rebalance` · 선착장/앵커/섬 로그는 **하나도 안 찍힙니다.**
Cowork 쪽 `?_=타임스탬프` 는 브라우저 캐시만 우회하고 서버 캐시는 못 뚫습니다.

## 2. 고칠 것 (둘 중 하나, 권장 ①)

```
① COURSE_ALGO_VERSION 22 → 23   (동작 변경 없음 · 캐시만 새로)
② course-brief 에 ?refresh=<CRON_SECRET 또는 ADMIN 토큰> 이면 캐시 건너뛰고 재생성 + 결과로 캐시 덮어쓰기
   (토큰 없으면 무시 — 공개 파라미터로 재생성 폭주 방지)
```

①은 즉시 되고, ②는 앞으로 원인 조사 때마다 재사용할 수 있습니다. 여유 있으면 둘 다.

**생성 트리거는 course-brief 만 쓰세요.** course-open 은 쓰지 않습니다(과거 사용자 플랜 덮어쓰기 사고).

## 처리 결과

### §2① — 완료 (`COURSE_ALGO_VERSION` 22 → 23)
동작 변경 없음. #288의 진입/분기 로그가 `cache-hit`에 가려지지 않도록 v22 최종 브리프 캐시를 새 키(`…:v23`)로 비운다. 지적대로 v22 캐시가 남아 있으면 로그가 `cache-hit` 한 줄뿐이라 맞는 판단이었다.

### §2② — 완료 (`?refresh=<CRON_SECRET>`)
- `GET /api/content/course-brief?region=…&days=…&refresh=<토큰>`: 토큰이 `CRON_SECRET`과 정확히 같으면(상수 시간 비교) 저장된 브리프를 읽지 않고 새로 만들고, 결과가 캐시 가능하면 기존 쓰기 경로가 덮어쓴다. 로그 `path=refresh key=…`가 남는다.
- 토큰이 없거나 다르거나 `CRON_SECRET`이 미설정이면 **조용히 무시**(일반 요청으로 처리, 무효 토큰이면 로그 한 줄만). 공개 파라미터로 재생성이 폭주하지 않는다.
- 전용 토큰(ADMIN)을 새로 만들지 않고 이미 배포돼 있는 `CRON_SECRET`을 재사용했다. **토큰이 URL 쿼리에 실리므로 호출 URL이 접근 로그에 남을 수 있다** — 조사용으로만 쓰고, 필요하면 회전한다.
- 생성 트리거는 course-brief뿐이다(course-open은 손대지 않음).
- 테스트: 라우트 테스트 2건(토큰 일치 시에만 `refresh:true`, 틀린 토큰·토큰 없음·비밀 미설정은 `false`).
