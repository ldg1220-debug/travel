## 2. ★★ 대표 하루를 "스팟 최다"로 고르니 이상치가 따라옵니다

후쿠오카 3일 코스의 OG 이미지입니다.

```
선택된 날:  하카타 도심 6곳  +  다자이후 텐만구 1곳
결과:      도심 6곳이 좌상단 구석에 뭉치고,
           화면 대부분이 다자이후까지 가는 빈 교외
```

**한 날만 그리기는 적용됐는데, 그 날 안에 15km 밖 스팟이 있으면 똑같습니다.**

### 수정 — 둘 중 하나

```
(a) 경계 계산에서 이상치 제외
    스팟들의 중앙 좌표에서 크게 벗어난 것(예: 중앙값 거리의 3배 초과)은
    경계 상자에서 빼고, 마커만 찍는다 (화면 밖이면 안 보여도 됨)

(b) 대표 하루를 "가장 조밀한 날"로 선택
    스팟 수가 아니라 경계 상자 대각선이 가장 짧은 날
```

**(a)를 권합니다.** 스팟이 많은 날이 대표로서는 맞고, 축척만 고치면 됩니다.

## 3. ★★ 계획 OG 지도의 경로선이 직선입니다

같은 이미지에서 하카타 → 다자이후가 **완전한 직선 대각선**입니다.

```
course-brief 지도   실제 도로 경로     ✅ (목포 이미지 확인)
계획 OG 지도        직선             ❌
```

**계획(`placesData`)에는 경로 정보가 없어서** 좌표만 잇고 있습니다.
동근님이 지난번에 지적하신 "다닐 수 없는 길"이 **공유 카드에서 재현됩니다.**

### 수정

```
planMapImage 에서 대표 하루의 구간들을 /api/routes 로 조회
  → estimated=false 인 구간은 실제 경로선
  → estimated=true 인 구간은 회색(#5 방식과 동일)
```

**엔드포인트는 이미 있습니다.** 구간 수가 하루치라 많아야 5~7개입니다.

## 5. AutoPipeline 질문에 대한 답 — 0km 판단이 맞습니다

> "혹시 실제로 (총 0km)가 나온 사례가 있으면 알려주세요"

**본 적 없습니다.** 제가 `dayTotals`에 `distanceKm: 0`이 있는 걸 보고
예방적으로 말씀드린 것이고, 실제 출력에서 확인한 게 아닙니다.

`0`이 falsy라 이미 생략되고 있다는 판단이 맞습니다. **주석만 남긴 처리가 적절합니다.**
제가 코드를 안 보고 말한 것이라 불필요한 작업을 시킬 뻔했습니다.

`COURSE_ALGO_VERSION`을 올리지 않은 판단도 맞습니다 — 코스 데이터가 아니라
이미지 구도만 바뀌었으니 26시간 TTL로 충분합니다.
