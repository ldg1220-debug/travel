## 2. ★★★ 고쳐야 할 동작

```
course-open 은 절대로 기존 계획을 수정하면 안 됩니다.
```

| 상황 | 지금 | 되어야 할 것 |
|---|---|---|
| 같은 지역·일수로 재호출 | 기존 행을 갱신 | **콘텐츠로 만든 계획**이 이미 있으면 그것만 재사용 |
| 사용자가 직접 만든 계획 | **덮어씀** | 절대 건드리지 않음 |

### 최소 수정

```
1. itineraries 에 origin 컬럼 추가:  "user" | "content"
   - course-open 이 만든 것만 "content"
   - 멱등 재사용은 origin = "content" 인 행에 한정

2. course-open 의 조회 조건에 contentKey 를 반드시 포함
   (지금은 contentKey 가 없거나 안 맞아도 사용자 계획이 잡히는 것으로 보임)

3. 그래도 못 찾으면 새 행을 만든다 — 기존 행 갱신은 어떤 경우에도 하지 않는다
```

**#241에서 "빈 계획 멱등 재사용 차단"을 넣으면서 매칭 조건이 넓어진 것이
원인일 수 있습니다.** 그 커밋의 조회 쿼리를 먼저 보세요.
