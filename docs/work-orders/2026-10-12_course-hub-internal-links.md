# 작업 지시서 — 코스 페이지가 "고아" 입니다: 홈 · /course 에서 링크 0개 → 코스 허브 만들기

작성: 2026-10-12 · 대상: **트레쥴** (`ldg1220-debug/travel`)
근거: 라이브 SSR HTML 실측 · Google Search Console(색인 5페이지, 사이트맵 마지막 읽음 10/6)

## 0. 먼저 — 이 지시서를 저장소에 보관

1. `docs/work-orders/2026-10-12_course-hub-internal-links.md` 로 저장
2. **완료된** 지시서 중 오래된 것부터 지워 10개 유지 (미완료 건은 남길 것)
3. 본 작업과 **같은 PR에** 포함

## 0-1. 배경

- 코스 페이지 `/course/{지역}/{N박M일}` 은 #300 부터 200 · JSON-LD · 사이트맵 등록(현재 59개+).
- 하지만 **사이트의 어떤 상위 페이지에서도 코스 페이지로 가는 링크가 없습니다.** 코스 페이지끼리만 서로 링크(같은 지역 다른 일수 · 같은 나라 다른 지역).
- Google 은 사이트맵만으로 발견한 링크 없는 페이지를 "발견됨 – 현재 색인 생성되지 않음" 으로 오래 둡니다(지금 5개가 이 상태).

## 1. 실측

```
SSR HTML 의 /course/{지역}/{일수} 링크 수
  /           0      (h1 "안녕하세요", 링크는 /planner · /trip/*)
  /course     0      (코스 만들기 화면)
  /discover   0
  /course/오사카/2박3일   7  (같은 지역 · 같은 나라)
Search Console  색인 5 · 발견됨-미색인 5 · 크롤링됨-미색인 1 · 사이트맵 마지막 읽음 2026-10-06 (코스 URL 추가 전)
```

## 2. 만들 것

```
① /course/all (또는 /courses) — 코스 허브 (SSR, 정적 링크)
   나라 → 지역 → 일수 칩(N박M일) 그룹. 링크는 "최근 30일 200 기록" 조합만(사이트맵과 같은 소스)
   각 지역 카드: 대표 명소 2곳 · 일수 칩들 · 지도 썸네일(있으면)
   title "여행 코스 모음 — {N}개 도시 · 일자별 동선 | 트레쥴"
② /course/{지역} — 지역 허브 (선택, 여유되면)
   그 지역의 모든 일수 링크 + 일수별 곳 수 · km
③ 홈 · /course · /discover 에 "인기 여행 코스" 섹션 — 허브 대표 8~12개 링크 + "전체 보기 → 허브"
   서버 렌더(크롤러가 JS 없이 읽을 수 있게)
④ 코스 페이지 브레드크럼에 허브 · 지역 허브 링크 (BreadcrumbList JSON-LD 와 일치)
⑤ 사이트맵에 허브 페이지 추가 (priority 0.8)
```

주의: 허브 링크는 공개 코스 페이지뿐. `/planner` · `/trip` · course-open 은 넣지 않음. Drive 는 허브에도 로드(코스 계열 페이지 정책과 동일).

## 처리 결과

지시서의 ①~⑤를 모두 처리했다(②는 "선택"이었지만 같이). 라이브 확인은 못 했다.

### ① 코스 허브 `/course/all` — 완료
- 서버 렌더 정적 링크: 범위(국내 → 해외) → 나라·광역 → 지역 카드(지역명 → 지역 허브 링크, 대표 명소 2곳, 일수 칩 `N박M일` → 코스 페이지, 지도 썸네일). 링크는 사이트맵과 같은 소스 — 현재 버전 브리프 캐시에서 판정한 조합 ∪ 최근 30일 버전 무관 기록(`fetchConfirmedCoursePages`). 허브의 코스 링크 수 = 확인된 조합 수(테스트로 고정).
- title `여행 코스 모음 — {N}개 도시 · 일자별 동선 | 트레쥴`, canonical `/course/all`, JSON-LD CollectionPage(코스 ItemList) + BreadcrumbList. Drive 로드, /planner·/trip·course-open 링크 없음(테스트).
- 카드 요약(대표 명소·썸네일)은 **현재 버전 캐시에 있는 조합**에만 있다 — 버전 무관 기록만 남은 조합(캐시 만료·버전 업)은 링크만 나온다.
- `flatRegions`에 없는 지원 지역(서울·부산·제주·인천 광역명 등)은 자기 자신을 묶음으로 삼는다 — 테스트에서 발견: 처음엔 이런 지역이 허브에서 통째로 빠졌다.

### ② 지역 허브 `/course/{지역}` — 완료
그 지역의 확인된 모든 일수 링크 + 일수별 곳 수·km·대표 명소, 브레드크럼(홈 > 허브 > 지역), `ItemList + BreadcrumbList` JSON-LD. 별칭은 정본으로 영구 리다이렉트, 미지원 지역은 404. **확인된 조합이 하나도 없으면 200 빈 페이지 + `noindex`** — 코스 페이지 브레드크럼이 이 주소를 가리키는데 그 코스 페이지가 막 만들어져 아직 기록이 없을 때 404가 되지 않게 했다(지시서에 없던 결정).

### ③ 인기 여행 코스 섹션 — 완료
홈·`/discover`·`/course`의 서버 컴포넌트 페이지에 `PopularCoursesSection`을 붙였다(클라이언트 화면 **아래**에 이어 붙는 정적 링크 목록 — 크롤러용). 지역당 1개(3일 우선, 없으면 가까운 일수), 해외 인기국 순 → 국내 → 이름 순, 최대 12개 + "전체 보기 → /course/all". 확인된 조합이 없으면 아무것도 그리지 않는다.
- **주의(영향)**: 이 섹션이 DB를 읽어 세 페이지를 `force-dynamic`으로 바꿨다 — 홈(`/`)·`/discover`·`/course`는 이전에 정적 생성이었다. 목록은 10분 메모라 DB 부하는 작지만 정적 캐시 이점은 사라진다. 대안(ISR + 빌드 시점 DB)은 CI 빌드에 DB가 없을 때 위험해 택하지 않았다.
- **한계**: 이 앱 셸은 화면 높이를 채우는 클라이언트 UI 구조라 섹션이 사용자 눈에는 스크롤 아래에 있거나 보이기 어려울 수 있다 — 크롤러(JS 없이 HTML 읽기)에는 충분하지만 사용자 노출은 라이브/디자인 확인이 필요하다.

### ④ 브레드크럼 — 완료
코스 페이지 화면의 브레드크럼을 `트레쥴 › 여행 코스 모음(허브) › {지역}(지역 허브) › {일수}`로, BreadcrumbList JSON-LD도 같은 4단계로 맞췄다(이전: 홈 › AI 추천 코스 › 코스).

### ⑤ 사이트맵 — 완료
코스 허브(`/course/all`)와 확인된 지역마다 지역 허브(`/course/{지역}`)를 priority 0.8로 추가했다(확인된 코스가 하나라도 있을 때만, lastmod = 그 안의 가장 최근 브리프 시각).

### 지시서와 다르게 한 것
- 허브 title의 `{N}개 도시`는 확인된 **지역 수**(서울·부산 같은 광역명도 1개로 센다).
- 사이트맵·허브가 같은 소스를 쓰지만 허브 링크 수와 사이트맵의 코스 URL 수는 10분 메모 시점 차이로 잠시 다를 수 있다.

### `COURSE_ALGO_VERSION` — 변경 없음 (브리프 내용 불변)

프로덕션 접근 불가. Search Console의 "발견됨 – 미색인"이 실제로 줄어드는지는 배포 후 구글 재크롤을 기다려야 한다.
