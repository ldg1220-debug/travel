## 2. ★★★ 1km 미만 구간은 경로 조회를 안 합니다

`/api/routes` 실측입니다.

```
텐진 지하상가 → 야키토리 무사시 (0.5km)   432m / 5분   path  2점  ← 직선
캐널시티 → 텐진          (1.0km)   1,281m / 18분  path 25점  ← 도로
경주 도보권            (0.6km)     393m / 5분   path  2점  ← 직선
```

**`path`가 2점이면 출발·도착만 이은 직선입니다.**

`#242`의 설계 그대로입니다.

```
도보 구간(WALK_MAX_KM 이하)은 실경로 조회 대상이 아니다
— 카카오모빌리티가 자동차 경로만 제공하고, 짧은 구간까지 API를 태우는 건
   비용 대비 효과가 낮다
```

**국내 기준으로는 맞는 판단이었는데, 해외에도 같이 적용돼 있습니다.**

## 3. ★★★ 해외는 구글 도보 경로가 됩니다 — 확인했습니다

브라우저에서 `DirectionsService`를 직접 불러봤습니다.

```
후쿠오카 0.5km 도보  →  status OK,  경로 30점,  0.6km   ✅
경주     0.6km 도보  →  ZERO_RESULTS                    ❌
```

**일본은 도보 경로가 나오고, 한국은 안 나옵니다.**
(구글이 한국 도보 길안내를 제공하지 않습니다 — 지도 데이터 반출 제한)

### 수정

```
routeSegment(scope, a, b, mode)

  mode === 'walk' 이고 scope === 'overseas'
    → fetchGoogleDirectionsRoute(a, b, 'walking')   ← 새로 태움
  그 외 (국내 도보)
    → 기존 직선 추정 유지
```

**해외 도보만 바꾸면 동근님이 보신 후쿠오카 문제는 해결됩니다.**

> 호출이 늘어납니다. 3일 코스에 도보 구간이 5~6개면 그만큼 추가인데,
> `course_cache`에 저장되니 지역·일수당 1회입니다. `ROUTING_BUDGET_MS`(15초)
> 안에 들어오는지만 확인하세요.

## 4. ★★ 국내 도보는 직선일 수밖에 없습니다 — 그럼 티를 내세요

```
국내 도보 구간에 쓸 수 있는 경로 API가 없습니다.
· 구글      ZERO_RESULTS
· 카카오모빌리티  자동차 전용
```

**직선을 그리는 것 자체는 어쩔 수 없습니다. 문제는 실선으로 그린다는 것입니다.**
사용자는 그 선이 실제 길이라고 읽습니다.

```
실제 경로 있음  →  실선
직선 추정       →  점선
```

### 왜 지금 점선이 안 나오는가

`#246`에서 점선 폴백을 넣으셨는데, 조건이 **`path === null`** 입니다.
그런데 직선 폴백은 **`path`에 좌표 2개를 채워서** 돌려줍니다.

```
path = [출발, 도착]   →  null 이 아님  →  실선으로 그려짐
```

**조건을 바꾸세요.**

```jsonc
// /api/routes 응답에 추가
{ "distanceM": 432, "durationMin": 5, "path": [...], "estimated": true }
```

```
estimated === true  →  점선
```

`path.length <= 2`로 판별해도 되지만, **서버가 명시하는 쪽이 안전합니다.**
실제 경로가 우연히 2점일 수도 있습니다.

## 5. ★ 정적 지도에도 같이 적용하세요

`course-brief`의 지도 이미지도 같은 구조입니다.
Static Maps는 점선을 못 그리니, **색을 흐리게** 하면 구분됩니다.

```
실제 경로  0x1E88E5cc  (진한 파랑)
직선 추정  0x9E9E9E88  (회색, 반투명)
```

블로그 이미지에서도 "이 구간은 추정"이 보입니다.
