  primaryType ∈ { airport, international_airport, bus_station, train_station, transit_station }
  이름  /공항|airport|terminal|터미널/i

## 3. ★★★ "스파 하루 1곳" 이 안 지켜집니다

```
세부 d3   1일차  Sage Health Spa · House of Lechon · Cheeva Spa · 풍류정바닐라드
                 ↑ 스파 2곳
```

**코스 전체 상한(⌈days/2⌉)은 지켜졌는데 하루 상한이 깨졌습니다.**
`capResortSpaSpots` 가 **일자 배분(`reallocateStopsByDay`) 전에** 돌아서, 배분이 스파 두 곳을 같은 날에 놓는 것으로 보입니다.

```
하루 상한은 배분 후에 검사하세요.
  같은 날 스파 2곳 → 한 곳을 스파 없는 날로 옮기거나 제외
```

## 처리 결과

### §2 — 완료 (공항·교통 시설 제외)

`src/lib/server/courseRecommend.ts`에 `isTransitFacility(p: Place)`를
추가했다: Google `primaryType`이 `airport`/`international_airport`/
`bus_station`/`train_station`/`transit_station` 중 하나이거나, 이름이
`/공항|airport|terminal|터미널/i`에 걸리면 제외한다 — 지시서가 제시한
조건 그대로다. `isTravelAgency`와 같은 자리(`fetchSlotCandidates`의
읽기 시점 필터)에 추가해 전 테마 공통으로 적용했다 — 공항·버스/기차역은
어느 테마에서든 방문지가 아니기 때문이다. "페리 선착장은 건드리지
말라"는 지시대로 타입 목록·이름 패턴 어디에도 선착장/페리/ferry는
넣지 않았고, 회귀 테스트로 `ferry_terminal` 타입·"선착장" 이름이
걸리지 않는지 확인했다.

**알려진 한계(지시서 원문 그대로 구현한 결과)**: "터미널"이라는 단어는
실제 항구의 여객터미널(예: "OO국제여객터미널")에도 흔히 쓰인다 —
지시서가 준 이름 패턴을 그대로 따랐기 때문에, 이런 이름의 실제 페리
터미널이 있다면 이 필터에 함께 걸릴 수 있다. 지시서가 명시한 "페리
선착장은 건드리지 말라"는 뜻을 최대한 살렸지만(선착장/페리 관련 단어는
전혀 넣지 않음), "터미널"이라는 단어 자체가 주는 이 긴장은 패턴을
정확히 그대로 따른 이상 남는다 — 실제로 이런 이름의 장소가 코스에
등장하는지는 이 세션이 라이브로 확인할 수 없었다.

### §3 — 완료 (스파 하루 상한을 배분 후로 이동)

원인 진단이 정확했다 — `capResortSpaSpots`(당시 이름)가
`reallocateStopsByDay`(지리적 재배치) *이전*에 하루 1곳 상한까지
같이 걸었는데, 재배치가 "어느 날"을 다시 정하므로 재배치 이전에 건
하루 상한은 재배치 이후엔 의미가 없었다. 함수를 둘로 쪼갰다:

- `capResortSpaSpotsTotal(dayStops, days)` — 코스 전체 ⌈days/2⌉곳
  상한만 재배치 *이전*에 건다(재배치가 고를 후보 자체를 미리 줄여두는
  효과는 유지).
- `capResortSpaSpotsPerDay(dayGroups)` — 하루 1곳 상한을
  `reallocateStopsByDay` 직후(최종 날짜 배정이 확정된 시점)에 새로
  건다.

`buildBrief`에서 `reallocateStopsByDay(composedDayStops)` 바로 뒤,
`preferRatedFirstStop` 호출 이전에 `capResortSpaSpotsPerDay`를 추가했다
— 순서·구간 이동시간이 아직 확정되지 않은 시점이라 스팟을 빼도
어긋나지 않는다. 회귀 테스트로 "재배치 이후 같은 날에 스파 2곳"
시나리오를 직접 재현해 검증했다(하루 1곳만 남고, 다른 날의 단독
스파는 그대로 유지되는지 둘 다 확인).

### §4 — 완료 (해외 한식당 코스 전체 1곳 이하)

`courseRecommend.ts`에 `isKoreanRestaurant(p)` 추가(Google
`primaryType === "korean_restaurant"` 또는 이름에 korean/한식/한국).
`courseBrief.ts`에 `capOverseasKoreanRestaurants(dayStops)`를 추가해
`scope === "overseas"`일 때만(국내 코스는 당연히 한식이 대부분이라
적용 안 함) 코스 전체에서 가장 인기 있는 한식당 1곳만 남기고 나머지는
뺀다 — 대체하지 않는다(다른 캡 함수와 같은 원칙). 지시서가 "해외 코스"
(휴양형 한정이 아님)로 표현해, 테마·스타일과 무관하게 해외 전체에
적용했다. "급하지 않다"는 지시서 표기대로 §2·§3 뒤에 처리했지만,
이번 라운드 순서표(§5) 안에 포함돼 있어 함께 완료했다.

### `COURSE_ALGO_VERSION` — 완료 (11→12)

§2·§3·§4가 모두 `courseBrief.ts`의 최종 브리프 조립 로직과
`fetchSlotCandidates` 읽기 시점 필터에만 있어 원본 후보 캐시와 무관하게
이 버전에만 반영된다. 버전을 올리지 않으면 세부 d3·d7 같은 지역이
26시간 동안 공항·스파 중복이 그대로인 옛 구성을 반환하므로, 12로 올렸다.

### 검증 관련 메모

이 세션은 프로덕션 Vercel 로그·GCP 콘솔·라이브 API 호출에 접근할 수
없어, §6 표의 실측(세부 d3·d7 공항 없음/하루 스파 ≤1/한식 ≤1, 경주·
서울·방콕 회귀 없음)은 코드 검토와 단위 테스트로만 검증했다. Cowork가
배포 후 §6 표 그대로 재현 확인해야 한다 — 특히 "터미널" 이름 패턴이
실제 항구 시설을 오탐하는지는 라이브 데이터 없이는 확인 불가능했다.
