## 1. ★★★ `/course-test` 가 원인을 확정했습니다

**진단 라우트를 만드신 판단이 정확했습니다.** 한 번에 갈렸습니다.

```

   본문: "course-test OK — region=경주 days=3  스팟 12곳 · 총 19.8km"

/course/경주/2박3일            →  404 · 751ms
```

```
같은 getCourseBrief 파이프라인
같은 라우트 그룹 (app)
같은 배포
차이는 세그먼트가 ASCII 냐 한글이냐 하나뿐
```

**라우트도 배포도 파이프라인도 전부 정상입니다.**
Vercel 로그의 `region="%EA%B2%BD%EC%A3%BC"` 와 정확히 일치합니다.

> **`params` 미디코딩이 유일한 원인으로 확정됐습니다.**
> 선행 지시서의 `safeDecode` 만 적용하면 끝납니다.

`/course-test` 는 고친 뒤 지워주세요. 역할을 다했습니다.

## 7. 처리 결과 (이 세션이 추가)

### §1 — `/course-test` 제거, 완료

`safeDecode`(이 세션 구현명은 `normalizeParam`) 적용을 확인한 뒤
`src/app/(app)/course-test/` 디렉터리 전체를 삭제했다. `next build` 결과
라우트 목록에서 `/course-test/[region]/[days]`가 사라지고
`/course/[region]/[days]`만 남은 것을 확인했다.

### §2 — `COURSE_ALGO_VERSION` 상향, 완료

`src/lib/server/courseBrief.ts`의 `COURSE_ALGO_VERSION`을 9 → 10으로
올렸다. `briefCacheKey`가 이 값을 캐시 키에 그대로 포함하므로
(`content-brief:{scope}:{region}:{days}:v{COURSE_ALGO_VERSION}`),
배포 즉시 기존 캐시 전체가 새 키로 취급되어 재생성된다. 워밍 크론
수동 실행은 이 세션에 실행 권한이 없어 직접 하지 못했다 — Cowork가
배포 후 실행해야 한다.

### §3 — 빈약한 캐시, 읽기 경로도 반영, 완료

`isFreshBriefPayload`(캐시 읽기 경로, `readBriefCache`가 호출)에
`payload.spots.length < MIN_VIABLE_SPOTS`이면 캐시 미스로 취급하는
분기를 추가했다. 기존에는 `ratingSource`/`distanceSource`/`dayTotals`
필드 존재 여부만 확인했는데, 필드는 다 있지만 스팟 수만 부족한
빈약한 브리프(고베 d2/교토 d1/오사카 d2가 (b) 케이스였을 경우)도
이제 캐시 미스로 처리돼 재생성된다. `MIN_VIABLE_SPOTS`는 기존
`isCacheableBrief`(#268, 쓰기 경로 가드)가 쓰던 것과 동일한 상수를
재사용했다 — 읽기/쓰기 양쪽이 같은 기준을 쓰게 됐다.

고베 d2/교토 d1/오사카 d2가 (a)(422 응답 자체가 캐시됨)였는지
(b)(스팟 부족 brief가 캐시됨)였는지는 이 세션에 프로덕션 DB
접근 권한이 없어 직접 확인하지 못했다 — 다만 이번 수정은 어느
경우든 안전하다: (a)면 애초에 `CourseBrief` 형태가 아니거나
`isFreshBriefPayload`의 다른 필드 검사에서 이미 걸러졌을 것이고,
(b)면 이번에 추가한 검사가 정확히 그 케이스를 잡는다.

### 테스트

`courseBrief.test.ts`의 `isFreshBriefPayload` 테스트 스위트를
확장했다: 기존 `payload()` 헬퍼가 스팟 1개만 만들고 있어 이번
변경으로 그 자체가 실패하게 됐으므로, 헬퍼를 스팟 3개(=MIN_VIABLE_SPOTS)를
만들도록 고치고, 스팟 2개짜리 얇은 payload가 `false`를 반환하는
케이스를 새로 추가했다.

### §4 — 사이트맵 플래그, 이번 라운드에서는 다루지 않음

두 지시서 모두 "200 확인 후"로 게이트를 걸었다. 이 세션은 프로덕션에
접근할 수 없어 실제 200 확인을 할 수 없으므로, `COURSE_PAGES_IN_SITEMAP`은
이번에도 플립하지 않았다. Cowork가 §6/8 체크리스트 확인 후 별도로
플립해야 한다.
