## 2. ★★★ 문제 ① — 지역 목록이 캐시 때문에 옛것으로 나갑니다

```
GET /api/content/regions            →  137곳 · 22개국 · 필드 {name, parent}        ← 옛것
GET /api/content/regions?cb=아무값    →  153곳 · 26개국 · 필드 {name, parent, popularity}  ← 새것
```

**배포 후 몇 시간이 지났는데 쿼리 없는 주소는 아직 #267 이전 목록입니다.**

```
route.ts
  export const revalidate = 86400;
  Cache-Control: public, max-age=86400, s-maxage=86400
```

**배포가 이 캐시를 비우지 않습니다.** CDN 이 최대 24시간 옛 응답을 줍니다.

### 이게 실제로 사고를 냈습니다

AutoPipeline 이 이 주소를 **쿼리 없이** 불러 스냅샷을 만듭니다.
그래서 동근님이 "코타키나발루" 를 넣었을 때 **"트레쥴이 지원하지 않는 지역입니다"** 가 떴습니다.
**트레쥴은 이미 지원하고 있었습니다.**

```
Cache-Control: public, s-maxage=3600, stale-while-revalidate=86400
export const revalidate = 3600;
```

**1시간이면 충분합니다.** 목록이 자주 바뀌지는 않지만, 바뀌었을 때 하루 늦게 반영되면 안 됩니다.

동근님이 물어보셔서 소스를 확인했습니다.

```

export type WorldCity = [country, city, lat, lng];

```

**그러니 수요 있는 지역은 웹 검색으로 때우지 말고 여기 한 줄 넣는 게 맞습니다.**

## 8. 처리 결과 (이 세션이 추가)

### §2 — regions API 캐시 1시간, 완료

`src/app/api/content/regions/route.ts`의 `revalidate`를 86400 → 3600으로,
응답 헤더를 지시서가 제안한 그대로 `Cache-Control: public, s-maxage=3600,
stale-while-revalidate=86400`으로 바꿨다.

### §3 — 별칭 발리→우붓, 코타→코타키나발루 + 보홀 추가, 완료

`src/lib/discoverData.ts`의 `REGION_ALIASES`에 `발리: "우붓"`,
`코타: "코타키나발루"`를 추가했다. "발리" 자체를 `WORLD_CITIES`에 직접
올리지 않기로 한 기존 결정(9월 초 국내 동명 지역 오매칭 사고 이후,
우붓/쿠타/스미냑처럼 구체적인 동네 단위로만 등록하기로 한 결정)은
그대로 유지하고, 별칭으로만 우붓(이미 검증된 좌표)으로 연결했다.
"KK → 코타키나발루" 별칭은 추가하지 않았다 — "KK"는 실제 사용자
입력으로 흔히 관측된 사례가 지시서에 없어(코타와 달리 지역명 축약이
아니라 두문자라 오탐 위험도 있음), 이번엔 지시서가 명시한 "코타"만
반영했다.

"보홀"도 `WORLD_CITIES`(필리핀)에 좌표 한 줄로 추가했다 — 지시서 §5가
설명한 대로 좌표 카탈로그 한 줄 추가만으로 course-brief가 바로
동작하는 구조라 별도 큐레이션이 필요 없었다.

### §4 — 제안 같은 대륙 우선, 이번 라운드에서는 다루지 않음

`suggestOverseasRegions()`는 현재 요청받은 미지원 지역 문자열(예:
"모리셔스")을 대륙/국가로 매핑할 수단이 전혀 없다 — 이 파일의 기존
코드 자체가 "지역·테마 taxonomy가 생기면 그때 문맥 기반으로 좁히면
된다"고 이미 명시적으로 이 결정을 다음으로 미뤄뒀다. "모리셔스"처럼
카탈로그에 아예 없는 임의의 지명을 대륙에 배정하려면 세계 지명
사전이나 실시간 지오코딩이 필요한데, 둘 다 이번 "소" 규모를 넘는
별도 데이터/비용이 드는 작업이다. 지시서 자체도 "급하지 않습니다"로
명시했고, §3의 발리 별칭으로 가장 큰 구멍은 이미 막혔다고 판단해
이번 라운드에서는 보류했다.
