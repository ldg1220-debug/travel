## 처리 결과

**실측 URL을 라이브로 확인하지 못했다.** 아래 원인은 코드로 확인한 것이고, 배포 후 Cowork 확인이 필요하다.

### §1 — 완료 (404 원인 두 개 · 로그)
지시서의 의심(`parseDays` 일수 상한 · 버전 캐시 키 불일치)은 아니었다. 페이지 입구(`loadEnabledCourseBrief`)는 `getCourseBrief`를 부르기 전에 두 가지로 걸렀다:
1. **허용목록**: `ENABLED_COURSE_PAGES`(국내 20곳 × 2박3일 + 서울·부산·제주·인천 1박2일, 24곳)에 없는 (지역, 일수)는 전부 404였다 — 오사카·도쿄·서울 2박3일·세부 7일 같은 조합은 course-brief API가 200이어도 페이지는 영원히 404였다. 9월 이후 지역·일수가 늘었는데 이 목록은 그대로였다.
2. **일수 세그먼트 형식**: 페이지 주소는 `/course/경주/2박3일`(라벨)만 인식했다. 지시서의 확인 URL(`/course/오사카/2`, `/course/경주/3` — 숫자)은 `labelToDays`가 null을 돌려줘 게이트에서 탈락했다. "9월에 200이던 `/course/경주/3`"은 예전에도 라벨 형식(`/2박3일`)으로만 200이었을 가능성이 높다 — 숫자 주소가 한 번이라도 200이었다는 근거는 코드에 없다.

수정: 입구를 `resolveCoursePageRoute`로 바꿨다 — (지원 지역 × 스타일별 일수 범위: 도시형 1~5 · 휴양형 2~7). 숫자 일수(`/course/오사카/3`)와 별칭(`/course/발리/…`)은 정본 라벨 주소로 **영구 리다이렉트**(404 아님). 범위 밖(도시형 6일·휴양형 당일치기)·미지원 지역은 404. 브리프 판정(`judgeCourseBrief` — 스팟 수·평점 절반·휴양형 해변)은 course-brief API·사이트맵과 같은 기준이다.
② 탈락 로그: `[course-page] gate rejected: region= daysSegment= reason=` / `[course-page] brief rejected: … reason=thin(spots= min= unrated=)|no-beach` / `[course-page] notFound: … reason=`(unsupported-region · unknown-days-segment · days-out-of-range · thin · no-beach · brief-threw).
- **지시서와 다르게 한 것**: 허용목록 제한이 사라져 크롤러가 지원 지역 × 일수(수백 개) 어느 주소든 열 수 있고, 캐시 미스면 라이브 생성(최대 60초)을 한다. 색인 노출은 사이트맵(확인된 조합만)이 정한다. `ENABLED_COURSE_PAGES`는 크론 우선 워밍과 후기→코스 링크에 남겼다.
- 회귀 테스트: 서울 1박2일 · 경주·오사카 2박3일 · 도쿄 당일치기 · 세부 5박7일(해변 있음) → 200, 세부 해변 없음·범위 밖 → 404, 숫자 일수·별칭 → 리다이렉트. (지시서의 "서울2·경주3·오사카3·도쿄1·세부7"은 라벨 `1박2일`·`2박3일`·`2박3일`·`당일치기`·`5박7일`로 시험했다.)

### §2 — 완료 (사이트맵에 코스 페이지, 단 점진적으로 자란다)
- `COURSE_PAGES_IN_SITEMAP`을 켰다. 목록은 허용목록이 아니라 **최종 브리프 캐시**(`content-brief:*:v{버전}`)에 있고 페이지 기준을 통과한 조합이다(`coursePageIndex.ts`) — 캐시에는 API 200 기준(`isCacheableBrief`)을 통과한 브리프만 쓰이므로 422 조합은 자연히 빠진다. `lastmod` = 브리프 생성 시각. 요청마다 수백 행을 읽지 않도록 필요한 필드만 SQL에서 뽑고 10분 메모한다. DB 장애면 코스 항목만 비고 나머지 사이트맵은 나간다.
- **한계(중요)**: 크론은 Hobby 플랜 하루 1회 · 회당 12건이다. 일반 워밍 풀을 **지역 × (도시형 1~5일 · 휴양형 2~7일) 전체**로 넓혔지만(기존 국내 1일·해외 2·3일은 부분집합) 한 바퀴 도는 데 수개월이 걸린다. 배포 직후 사이트맵의 코스 URL은 소수이고 `COURSE_ALGO_VERSION`이 오를 때마다 캐시가 비어 다시 자란다. 코스 페이지 방문도 캐시를 채운다. 더 빠르게 하려면 Pro 플랜 크론이나 배치 확대가 필요하다 — 90초 예산 실측 없이는 올리지 않았다.

### §3 — 완료 (검색 품질)
- **title**: `{지역} {일수} 코스 — {N}곳 · {대표1}·{대표2} | 트레쥴`(layout 템플릿과 겹치지 않게 `absolute`). 일수는 URL 라벨과 같다 — 지시서의 `{n-1}박{n}일`과 달리 6·7일은 "5박6일"·"5박7일"이다(9월 지시서의 표 그대로). **description**: `{지역} {일수} 코스: {대표 3곳}. 일자별 동선 지도 · 이동 시간 · 평점 정리.` 대표 명소는 식당·카페·술집·숙소·선착장·스파를 빼고 평점×리뷰 수 순.
- **canonical**: `courseCanonicalPath`(지역·라벨 모두 `encodeURIComponent`) — 사이트맵·내부 링크·canonical이 같은 함수를 쓴다.
- **본문(SSR)**: 표 대신 **일자별 카드**(N일차 · 곳 수 · 이동 km · 종일 시설 일정 표시, 장소별 종류·평점·다음 이동 텍스트). 차량 폴백·직선 추정 구간은 문구로 밝힌다(`toNextFallback`·`toNextSource`).
- **JSON-LD**: 기존 TouristTrip(itinerary = ItemList of TouristAttraction)에 `url` 추가 + **BreadcrumbList**(홈 > 코스 > 지역·일수).
- **내부 링크**: 같은 지역의 다른 일수, 같은 나라(국내는 같은 광역)의 다른 지역(지역당 1개, 같은 일수 우선). **확인된 조합(사이트맵 목록)만** 건다 — 404가 될 수 있는 페이지로 링크하지 않는다. 그래서 초기엔 링크가 적다.
- **CTA**: "이 코스로 내 일정 만들기" → 기존 `course-open`. course-open은 시스템 계정 소유의 콘텐츠 계획을 (지역, 일수, 버전)당 하나로 멱등 생성하고, 사용자 본인의 계획은 뷰어의 "담아가기"가 **새로 복사**한다 — 사용자의 기존 플랜을 덮어쓰지 않는다(코드로 확인: `ON CONFLICT`는 `origin='content'` 행만 대상).
