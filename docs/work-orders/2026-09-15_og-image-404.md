## 1. 메타태그는 잘 들어갔습니다

```
og:type         article                                          ✅
og:description  "3박 4일 · 19곳 · 캐널시티 하카타, 이치란 … 외"      ✅
og:image        /api/og/plan/{shareToken}.png                    ✅
```

설명이 정확히 요청한 형태입니다. **일수·장소 수·대표 장소명**이 다 들어갔습니다.

## 2. ★★★ 그런데 그 이미지가 404입니다

```
GET /api/og/plan/9854326a-d2ac-46d5-b88c-edf3e20bbdeb.png
→ 404  application/json
   {"error":"map not available for this plan yet"}
```

**3회 재시도, 4초 간격 — 전부 동일합니다.** 일시적 지연이 아닙니다.

### 왜 문제인가

```
og:image 가 404  →  카카오·페이스북 크롤러가 "이미지 없음"으로 캐시
                →  카드는 지금과 똑같이 심심하게 뜸
                →  캐시가 만료될 때까지 고쳐도 안 바뀜
```

**§1의 목표가 달성되지 않았습니다.** 오히려 없는 것보다 나쁠 수 있습니다 —
크롤러가 깨진 이미지를 기억합니다.

### 원인 추정

엔드포인트가 **이미 생성돼 있는 지도를 찾아 돌려주기만** 하는 것으로 보입니다.
`course-brief`의 지도는 `지역·일수` 캐시 키로 만들어지는데,
**사용자가 직접 만든 계획에는 그런 캐시가 없습니다.**

```
course-open 으로 만든 코스 계획   →  지도 있음 (course-brief 캐시)
사용자가 손으로 만든 계획         →  없음  ← 공유되는 건 대부분 이쪽입니다
```

### 수정

```
· 캐시에 없으면 그 자리에서 생성한다 (generateCourseMapImage 재사용)
· 생성 결과를 Blob에 저장하고 shareToken 기준으로 캐시
· 계획이 수정되면 무효화 (updated_at 을 캐시 키에 포함)
· 생성 실패 시 404 대신 기본 이미지를 돌려줄 것
    → 크롤러가 "이미지 없음"을 학습하지 않게
```

**마지막 항목이 중요합니다.** OG 이미지는 실패해도 200이어야 합니다.

## 4. AutoPipeline 질문에 대한 답 — 일차별 거리·권역은 없습니다

AutoPipeline 세션이 물어온 건입니다. 제가 응답을 확인했습니다.

```
course-brief 응답
  region, days, totalDistanceKm, spots[], imageUrl, appUrl,
  ratingSource, distanceSource

spots[] = { name, category, rating, reviewCount, lat, lng,
            order, day, toNextMinutes, toNextMode }
```

**일차별 거리도, 권역명도 없습니다.** 그 세션이 생략한 판단이 맞습니다.

### 넣으면 좋습니다 (선택)

지식iN 답변과 블로그 둘 다 `**1일차 (총 N km)**` 형태를 쓰고 싶어 합니다.
지금은 전체 거리만 있어서 1일 코스에서만 쓸 수 있습니다.

```jsonc
// 응답에 추가
"dayTotals": [
  { "day": 1, "distanceKm": 15.2, "spotCount": 4 },
  { "day": 2, "distanceKm": 6.5,  "spotCount": 3 }
]
```

**이미 구간별로 계산하고 있으니 합산만 하면 됩니다**(`assembleDaySpots`가 날짜별로 돕니다).
클라이언트가 좌표로 추정하면 직선거리라 틀립니다 — 서버가 줘야 합니다.

**권역명은 넣지 마세요.** "도심", "항만" 같은 건 사람이 붙이는 이름이라
자동 판정하면 틀립니다.
