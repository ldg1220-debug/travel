## 1. 왜 이게 지금 1순위인가

Search Console 실측입니다.

```
maeilg.com   28일  클릭 1 · 노출 38
tradule.co.kr 28일  클릭 0 · 노출 4
```

**검색 유입은 3개월째 0에 수렴합니다.** 편수를 늘려도 같은 결과가 나옵니다.

반면 **여행 계획은 본질적으로 공유됩니다.** 동행이 있으니까요.
앱에 `카카오톡 공유`가 이미 있고, 계획마다 `shareToken`도 있습니다.
**유일하게 작동할 수 있는 유입 경로인데 지금은 끊겨 있습니다.**

```
지금:  공유 링크를 받은 사람  →  계획을 본다  →  끝
```

받은 사람이 그 계획을 자기 것으로 만들 방법이 없습니다.

## 2. ★★★ 공유 링크에 담아가기

`#249`에서 **후기용** 담아가기를 만드셨습니다(`/api/trip-posts/[id]/copy`).
**계획 공유 링크에도 같은 것이 필요합니다.**

```
/planner/{shareToken}  를 남이 열었을 때

  ┌──────────────────────────────┐
  │  당근당근님의 오사카 2박3일 계획   │
  │  [내 계획으로 담아가기]          │
  └──────────────────────────────┘
```

### 엔드포인트

```
POST /api/itineraries/{shareToken}/copy
```

**`#249`의 copy 라우트를 그대로 본뜨세요.** 거기 설계가 맞습니다.

```
· INSERT 전용 — id 받지 않음, ON CONFLICT 없음
· origin='copy', sourceItineraryId 기록
· 날짜만 오늘 기준 재배치, 시각·체류시간 유지
· 제목: "{원제목} (복사)"
```

### 로그인 안 한 사람이 대부분입니다

공유 링크를 받는 사람은 **거의 전부 비로그인**입니다. 여기가 전환점입니다.

```
담아가기 클릭  →  비로그인이면
  1. 담기 의도를 sessionStorage 에 보관
  2. 로그인 유도
  3. 로그인 직후 자동으로 담아주고 그 계획으로 이동
```

`#249`에서 후기용으로 이미 만드신 흐름입니다. **재사용하세요.**

**로그인 화면만 띄우고 끝내면 거기서 다 이탈합니다.**

## 3. ★★ 공유를 유도하는 자리

지금은 `카카오톡 공유` 버튼이 하단 도구 모음에 다른 버튼들과 섞여 있습니다.
**계획을 다 짠 직후가 공유 확률이 가장 높은 순간**인데 그때 아무 말이 없습니다.

```
계획 저장 직후 토스트:
  "저장했어요.  동행에게 공유할까요?  [카카오톡으로 보내기]"
```

한 번만, 조용히. 매번 뜨면 짜증납니다.

---

## 4. ★ 공유 링크 화면이 지금 어떤지 확인해 주세요

제가 남의 계정으로 열어볼 수가 없어서 확인 못 한 부분입니다.

```
· 비로그인으로 /planner/{shareToken} 을 열면 무엇이 보이는가
· 작성자 이름이 보이는가
· 앱 소개나 가입 유도가 있는가
```

**비로그인 사용자에게 이 화면이 사실상 첫인상입니다.**
지금 계획만 덩그러니 보인다면, 최소한 "트레쥴로 이런 계획을 만들 수 있습니다"
정도는 있어야 합니다.

## 5. 측정

유입 루프는 **숫자가 안 보이면 고칠 수 없습니다.**

```
· 공유 링크 생성 수
· 공유 링크 열람 수 (비로그인 포함)
· 담아가기 클릭 수
· 담아가기 → 가입 전환 수
```

**최소한 마지막 두 개는 꼭 남기세요.** 관리자 대시보드가 이미 있으니 거기에 붙이면 됩니다.
