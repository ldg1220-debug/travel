## 확정 사항 (사용자 결정 완료)

### A. 국내 카드 지표 → **"트레쥴 큐레이션" 배지 + 카테고리·지역**

- 국내(Kakao) 스팟: `★평점` 대신 **큐레이션 배지 + 카테고리 · 지역** 표시
- 해외(Google) 스팟: 기존대로 `★평점 · 리뷰수` 표시
- 라이브 검색 스팟: 평점 있으면 표시, 없으면 카테고리만
- **빈 별점·0건·가짜 숫자 금지**

> 근거: 큐레이션 398곳의 가치를 오히려 강조하는 방향. 개발 부담 없음.

### B. 브랜드 컬러 → **토큰 값 교체 + 호출부 마이그레이션**

- #163에서 이미 `--color-brand-*` 시맨틱 토큰을 깔아뒀습니다
  ("정의만 추가하고 실제 호출부(indigo-500 등, 20여 파일 300곳+)는 범위가 커서 이번엔 안 건드림 — 다음 작업을 위한 밑작업만")
- **그 밑작업 위에 올라타세요.** 토큰 값을 warm 팔레트로 바꾸고, indigo 직접 호출부를 `brand-*` 토큰으로 마이그레이션
- `--color-success-*`(#163에서 이미 마이그레이션 완료), `--color-rating`은 그대로 유지

### C. 모바일 V2(피드형 홈) → **보류**

콘텐츠 볼륨이 필요한 화면인데, 방금 템플릿 스팟 84% 삭제(#164/#166)·숙소 섹션 숨김(#163)·
커뮤니티 카테고리 축소를 한 상태라 지금 만들면 다시 빈 화면이 됩니다.
카테고리 아이콘 5개 그리드도 기존 "메뉴판" 패턴의 재발입니다.
**콘텐츠·커뮤니티가 쌓인 뒤 재검토.**

## Phase 0 — 디자인 토큰 (지금 바로, 독립 브랜치)

`#166`·`#169`와 파일이 겹치지 않아 **병행 가능**합니다.

### 0-1. 접근성 수정 (필수)

직접 계산한 현재 목업 대비비입니다. 전부 WCAG AA 미달.

| 조합 | 현재 | AA 기준 | 조치 |
|---|---|---|---|
| `ink3 #8A7F72` on `bg #FAF7F2` | 3.67 : 1 | 4.5 | **`#6F6459` 내외로 어둡게** (≈4.6:1) |
| `ink4 #B8AD9F` on `bg #FAF7F2` | 2.07 : 1 | 4.5 | **텍스트 사용 금지** → 아이콘·구분선 전용. 비활성 탭 라벨은 `ink3` |
| `#fff` on `#FF8A3D` (그라데이션 좌) | 2.34 : 1 | 3.0(대) / 4.5(본문) | 그라데이션 위 본문에 **어두운 오버레이** `rgba(0,0,0,0.18)` 추가 또는 그라데이션 명도 하향 |
| `#fff` on `#FF4D8D` (우) | 3.14 : 1 | | 대제목만 허용, 본문 불가 |
| 그라데이션 텍스트 on 흰 배경 | 2.3~3.1 : 1 | | **로고 등 장식 전용.** "13일" 같은 정보성 숫자에는 사용 금지 |

`ink3`는 거의 모든 보조 텍스트(11~13px 카테고리·시간·설명)에, `ink4`는 모바일 탭바
10px 라벨에 쓰이므로 영향 범위가 넓습니다. **토큰 한 파일에서 잡는 게 가장 쌉니다.**

### 0-2. 브랜드 팔레트 적용

```
brand.orange   #FF8A3D
brand.pink     #FF4D8D
brand.gradient linear-gradient(90deg, #FF8A3D 0%, #FF4D8D 100%)
bg             #FAF7F2   surface #FFFFFF   surfaceAlt #F3EEE6
hairline       #EAE3D6   ink #1A1512 / ink2 #4A423B / ink3(수정값) / ink4(수정값)
```

- 위 0-1 수정값을 반영한 뒤 적용
- indigo 직접 호출부 → `brand-*` 토큰으로 치환
- 그라데이션 장식색(`discoverData.ts`의 `GENERATED_GRADIENTS` 등)은 의미가 달라 **제외**

### 0-3. 완료 조건

- 자동 대비 검사에서 본문 텍스트 조합 전부 AA 통과
- indigo 하드코딩(`indigo-`, `#6366f1`) 잔존 0건
- 기존 화면 렌더 회귀 없음 (Playwright 스냅샷)

## Phase 1 — 홈 V1 (#166·#169 병합 후)

목업: `HomeDesktopV1` / `HomeMobileV1`

**효과 대비 리스크가 가장 좋은 단계.** 진행 중 여행 1건만 있으면 성립하고,
현재 홈의 "동일 카드 5개 메뉴판" 문제를 바로 해결합니다.

### 구현

- **히어로를 상태 기반으로**: "부산 여행 13일 남았어요 / Day 2를 마저 짜볼까요?"

  → **완료 여행 0건인 사용자에게만 노출**, 1단계 완료 후 한 줄로 접기

## 컴포넌트 구현 메모

목업 코드 자체는 깔끔하나, 실제 구현 시 추가할 것:

- **`Button`에 `disabled`/`loading` 상태가 없습니다.**
  AI 코스 생성이 7~13초 걸리므로 **로딩 상태는 필수**입니다
- `Icon`은 인라인 SVG switch문 — 30개 넘으면 번들 분리 고려
- `ImgPlaceholder`(줄무늬)는 목업용. 실제로는 **#163에서 만든 카테고리 아이콘 워터마크 폴백** 사용
- 목업이 `Pretendard`·`Instrument Serif`를 참조합니다 — 폰트 로딩 여부 확인 필요
- `Chip`·`StatusPill`·`PlaceCard`는 토큰 기반으로 잘 분리돼 있어 그대로 옮기기 좋음

## Phase 0 구현 기록 (실제 반영값)

작업 시점: 2026-08-13 · 브랜치: `claude/redesign-phase0-tokens`

목업의 `#FF8A3D`/`#FF4D8D`는 흰 텍스트와 조합했을 때 각각 2.35:1 / 3.14:1로
AA 기준(4.5:1)에 크게 못 미쳤다 (0-1의 실측과 일치). 토큰화하며 단일 색이 아니라
**OKLCH 라이트니스 스케일**로 만들어, 원본 hex는 장식 전용 밝은 단(≈400)에 두고
실제 버튼/링크에 쓰이는 진한 단(600 이상)은 대비를 만족하도록 새로 계산했다.

| 토큰 | OKLCH | HEX(참고) | vs 흰색 |
|---|---|---|---|
| `--color-brand-500` (구 indigo-400 대응) | L68% C0.167 H50.5 | `#E67420` | 3.05:1 |
| `--color-brand-600` (구 indigo-500 대응, 흰 텍스트 버튼 기준선) | L56.5% C0.159 H50.5 | `#BC5200` | **4.83:1** |
| `--color-brand-700` (구 indigo-600 대응) | L46.5% C0.142 H50.5 | `#943A00` | 7.33:1 |
| `--color-brand-pink-600` (구 violet-500 대응) | L56.5% C0.207 H3.1 | `#CF246A` | **5.11:1** |

호출부 마이그레이션은 "같은 숫자 단끼리" 치환하지 않았다 — indigo-500(`#6366f1`)이
흰 배경 대비 4.47:1로 이미 AA 근처였던 반면, 같은 밝기의 warm 오렌지는 채도가
높아 지각 대비가 훨씬 낮다(2.35:1). 그래서 전체적으로 **한 단씩 진하게 밀어서
치환**했다: `indigo-500 → brand-600`, `indigo-600 → brand-700`, `indigo-300 →
brand-400` 등. 정확한 매핑 표는 PR 본문 참조.

**제외한 것** (의미가 "브랜드"가 아니라 "다양성"인 색이라 손대지 않음):
`discoverData.ts`의 스팟별 장식 그라데이션/색상 필드 전체, `ScrapbookClient.tsx`의
`COVER_GRADIENTS`(계획 커버 랜덤 배정)와 3색 `STATS` 트리오.

`ink3`/`ink4`/`bg`/`surface`/`hairline` 등 나머지 warm 팔레트는 토큰으로만
추가해뒀다(`--color-warm-*`) — 아직 어떤 화면도 쓰지 않는다. Phase 1이 홈 V1을
만들 때 그대로 가져다 쓰면 된다.
